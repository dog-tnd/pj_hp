# サイト共通ヘッダーの土台 requirements

## 目的
サイト共通ヘッダーを「PC版」と「モバイル版」の2つの実装を載せられる土台に作り替える。旧メニュー（`menu.tsx` / `MenuLayout.astro`）を撤去し、入会モーダルと画面幅の切り替えルールを1か所にまとめる。

PC版ヘッダー（別担当）が、ページ・モーダル・切り替えに触れず、見た目だけの作業で載せられる状態をゴールとする。PR #61 では、ヘッダー以外の作業（全ページの差し替え、develop の取り込み）で事故が起きたため、その部分を先に済ませておく。

## Non-goals
- PC版ヘッダーの中身・見た目（別担当・別 PR で作る。今回は差し込み口だけ用意する）
- モバイル版ヘッダーの見た目の変更（デザイン 2b のまま）
- 入会モーダルの見た目の刷新と開閉アニメーション（文言の統一だけ行う）
- 各ページ本文のデザイン調整（3カラム撤去で本文幅が広がることと、上の余白 80px が無くなること以外は触らない）
- about ページの改修（D案）
- ページ内リンクの着地位置の補正（`scroll-padding-top`）。現状ページ内リンクが無いため
- PR #61 の修正

## ユーザーストーリー
- サイト訪問者として、どのページからでも他のページへ移動したい。なぜなら、ページを読み終えた後に入部の情報や問い合わせ先を探すから。
- PC版ヘッダーの担当者として、ヘッダーの見た目だけを実装したい。なぜなら、全ページの差し替えやモーダルの実装は自分の担当範囲の外で、事故の元になるから。
- レビュー担当として、切り替えルールとモーダルがそれぞれ1か所にあってほしい。なぜなら、確認する範囲を絞れるから。

## 受け入れ条件

### 画面幅の切り替え
- [ ] 画面幅が 1024px 未満の間、システムはモバイル版ヘッダー（上部バーと右下の追従ボタン）を表示する
- [ ] 画面幅が 1024px 以上の間、システムはモバイル版ヘッダーを表示しない
- [ ] 画面幅が 1024px 以上の間、システムは PC版ヘッダーの差し込み口を描画する。中身は空で、何も表示されない
- [ ] システムは、ヘッダーの表示・非表示の条件を `SiteHeader.astro` の1か所にだけ持つ。例外は、追従ボタンと本文が重ならないための `<main>` の下余白だけとする
- [ ] もしモバイルのメニューを開いたまま画面幅が 1024px 以上になったら、システムはメニューを閉じ、背景のスクロール固定を解除する

### 入会モーダル
- [ ] システムは、入会モーダルを全ページで1つだけ描画する
- [ ] `data-open-join` を持つボタンが押されたとき、システムはその入会モーダルを開く（ボタンが何個あっても同じモーダルを開く）
- [ ] モバイルのメニュー内の「入会申し込み」が押されたとき、システムはメニューを閉じて入会モーダルを開く
- [ ] 入会モーダルが開いている間、システムはどの画面幅でも背景のスクロールを固定する
- [ ] 閉じるボタン・Escape・背景のクリックで入会モーダルが閉じたとき、システムはスクロール固定を解除する。ただしメニューが開いていれば固定を続ける
- [ ] システムは、モバイル版の文言（3段落）を表示する

### 旧メニューの撤去
- [ ] システムは、どのページからも `menu.tsx` と `MenuLayout.astro` を読み込まない
- [ ] 撤去したファイルは削除せず、`archive/unused-assets/` に退避する
- [ ] システムは、トップ・about・ブログ一覧・記事・FAQ・お問い合わせ・404 で、右160pxのナビ列（3カラム）を使わずに本文を表示する
- [ ] システムは、旧 `MenuLayout` が本文の上に付けていた余白（80px）を付けない
- [ ] 撤去後も、フォント（Noto Sans JP・Rubik Doodle Shadow）の表示は撤去前と変わらない

### 既存動作の維持
- [ ] モバイル版の既存の動作（開閉のフェード、ハンバーガーと × の位置ずれ補正、現在地の表示）は変わらない
- [ ] `pnpm build`（`astro check` を含む）がエラー0で完了する
