# 「プログラミングサークル」検索での AI による概要対策 フェーズ2 requirements

## 目的
Google で「プログラミングサークル」と検索したときの「AI による概要」に、TND（tus-tnd.com）が正しい事実で引用されるようにする（spec 003 の続き。issue #74）。

- フェーズ1（spec 003・#75）の `<head>` の対策は main にしか入っていない。develop に移し、事実を今のものに直す（D1）
- SNS で共有されたときに使える OG 画像を用意する
- ブログ記事の構造化データを、サイト全体の `Organization` につなげる

## 前提
- spec 003 は main にある。このブランチで develop に取り込み、フェーズ1の記録として残す（D1）
- サークルの事実はプロジェクトの `CLAUDE.md`「文言で守る事実」を正とする。spec 003 の説明文・meta に残る古い事実（デザインのチーム・週1回の勉強会・4〜5月の募集・約40名）は使わない
- 数字の事実（設立年・人数・初心者の割合・会費など）を並べて見せるのは about（D3）。about は PR #69 で刷新中

## Non-goals
- トップに数字の事実を載せること（D2）。トップの見える部分は変えない
- about の本文・h1・数字の一覧。PR #69 の担当者に、今の事実に合わせて直してもらう（D3）。このブランチでは about の `<Layout>` の `description` だけ直す
- よくある質問の質問・回答の文言（microCMS で管理。直すのは人間。「Open questions」）
- microCMS の記事の本文に入った h1（`9-aPL_QNLQSI`・`2025-09-25-shignate-mufg`）。コードでは対策せず、書き手が本文の見出しを「見出し2」から使う（D7）
- ブログ一覧（`/blog`）がインデックスされない原因の調査（spec 003 のフェーズ2の 6）。Search Console の数字が要るため、部内資料で行う
- `llms.txt`・`meta keywords` の整理・被リンクの獲得（spec 003 と同じ）

## ユーザーストーリー
- 大学のプログラミングサークルを探している高校生・大学生として、AI による概要に TND の規模・初心者の割合・活動内容が出てほしい。なぜなら、一般論より実例のほうが選ぶ参考になるから。
- TND の広報担当として、検索結果・AI による概要・SNS の共有で、TND が今の正しい事実（非公認・野田キャンパス・約20名・通年募集）で紹介されてほしい。なぜなら、古い事実や誤った紹介は新歓に悪影響だから。
- TND のページを SNS で共有する人として、共有したときにサークル名と画像のカードが出てほしい。なぜなら、文字のリンクだけでは見てもらえないから。

## 受け入れ条件

### サイト全体の `<head>`（`Layout.astro`。フェーズ1の移植）
- [ ] システムは、全ページの構造化データ（JSON-LD）を `@graph` で出力し、`Organization`（`@id` は `https://tus-tnd.com/#organization`）と `WebSite` を含める
- [ ] システムは、`Organization` に名前・別名・説明・URL・ロゴ・設立年・活動場所（東京理科大学 野田キャンパス、千葉県野田市）・扱う分野（`knowsAbout`）・SNS（X・GitHub）を含め、`memberOf` / `parentOrganization` を含めない（spec 003 D3）
- [ ] システムは、構造化データの説明文と `knowsAbout` に、今の事実だけを書く（デザインのチーム・勉強会の頻度・募集の時期を書かない。人数は約20名）
- [ ] システムは、構造化データの説明文に、サイト内のどこか（#69 で刷新した後の about を含む）に表示されている事実だけを書く
- [ ] システムは、`og:locale` に `ja_JP` を出力し、Twitter カードのメタタグを `name` 属性で出力する（X が定義していない `twitter:url` は出さない）
- [ ] システムは、JSON-LD の文字列中の `<` を `\u003c` にエスケープする
- [ ] システムは、`description` を渡さないページに、今の事実を含む既定の説明文を出力する

### ページごとの meta
- [ ] システムは、トップ・私たちについて・よくある質問・お問い合わせ・ブログ一覧に、それぞれ固有の `description` を出力し、どれにも古い事実を書かない
- [ ] システムは、トップの `<title>` を「プログラミングサークル」が前半に来る形にする
- [ ] システムは、各 `description` を 70〜120 字に収める
- [ ] システムは、人数を書くときは「約20名」と書く（D4）

### OG 画像
- [ ] システムは、1200×630 の PNG の OG 画像を `public/` に置き、`image` を渡さないページの `og:image`・`twitter:image` にする
- [ ] システムは、OG 画像の見た目を、キャンバス「ホーム刷新」の「OG 画像」（https://claude.ai/artifact/JNrMmJAdD4D6o7b5nEURC9 ）に合わせる（D5）
- [ ] システムは、OG 画像に、人数など変わりうる事実を入れない

### ブログ記事の構造化データ（`src/pages/blog/[slug].astro`）
- [ ] システムは、記事の `BlogPosting` の `publisher` を、`Organization` の `@id`（`https://tus-tnd.com/#organization`）の参照にする


### 共通
- [ ] `pnpm run build`（`astro check` を含む）が成功する
- [ ] 出力した JSON-LD がすべて `JSON.parse` できる
- [ ] 全ページの `<body>` は変わらない（変更前後のビルド結果で比べる。変えるのは `<head>` と、記事ページの JSON-LD だけ）

## 決定事項（2026-10-18、人間）
- D1：フェーズ1（#75）の `<head>` の変更を、このブランチで develop に移す。1月のリリースで develop を main に取り込むときは、develop 側を正として衝突を解く
- D2：トップには数字の事実を載せない。トップは見やすいものにする方針で、#74 の「トップの事実ブロック」は取り下げる
- D3：数字の事実は about に載せる。about を刷新している PR #69 の担当者に、今の事実（約20名・チームは2つ・通年募集）に合わせて直してもらう
- D4：メンバーは約20名（spec 003 の「約40名」は古い）
- D5：OG 画像は、キャンバス「ホーム刷新」の「OG 画像」の案で決定（大学名の英字・TND・「東京理科大学 野田キャンパスのプログラミングサークル」・tus-tnd.com・シンボル）
- D6：#74 の残りは1つの PR にまとめる
- D7：microCMS の記事の本文の h1 は、コードで対策しない。書き手が気をつける
- D8：この PR は、#69（事実を直した版）のマージ後にマージする。「約20名」などの事実が about に表示されてから、構造化データ・説明文に出すため
- D9：お問い合わせの説明文の「勉強会での登壇」（外部からの登壇依頼の意味）はそのまま残す

## Open questions
- よくある質問（microCMS の faq）に、デザインコースのツール・募集の時期（4〜5月）・勉強会の頻度（週1回）の質問が残っている。`FAQPage` の構造化データはこのデータから作られるため、`Organization` の説明と食い違う。直すか消すか（人間が microCMS で行う）
