# ブログ記事ページの刷新 requirements

## 目的
記事ページ（`/blog/[slug]`）を、上部固定ヘッダー（spec 001・PC版 #67）を前提にしたレイアウトに作り替える。旧3カラム（右ナビ列）の名残りで本文が中央の白いカードに収まっている現状をやめ、長い記事を読みやすくする。

あわせて、どの画面幅でも読んでいる途中で目次を開き、読みたい見出しへ移動できるようにする。

## Non-goals
- ヘッダー（`HeaderDesktop` / `HeaderMobile`）と入会モーダルの変更
- 著者プロフィール（ひとこと紹介・SNS リンク）。microCMS で集めていないため
- タグのリンク化・タグ別一覧ページ
- 関連記事の選び方の変更（現行のロジックのまま）
- ブログ一覧ページ（`/blog`）
- 本文の装飾（`.prose` の見出し・段落・表などのスタイル）の刷新。目次のための調整（見出しの `id` と着地位置）だけ行う
  - 注：`BlogArticleView.astro` の `.prose` 向けの独自スタイルは、Astro のスコープ付きスタイルのため `set:html` の本文には当たっておらず、今も効いていない。今回もグローバルにはしない（グローバルにすると本文の見た目が変わるため）
- microCMS の本文の中身（本文中の h1 など）の修正
- `TwoLine` の装飾
- パンくずの構造化データ（`BreadcrumbList`）

## ユーザーストーリー
- 読者として、長い記事を目の負担なく読みたい。なぜなら、技術記事は1本が長く、行が長すぎると読み疲れるから。
- 読者として、読んでいる途中で目次を開き、読みたい見出しへ移動したい。なぜなら、技術記事は必要な部分だけ読むことが多いから。
- スマホの読者として、目次が本文を隠さないでほしい。なぜなら、画面が狭く、常に出ている目次は本文を読む邪魔になるから。
- 記事を書くメンバーとして、目次を手で作らずに済ませたい。なぜなら、microCMS で見出しを付けるだけで目次になってほしいから。

## 受け入れ条件

### レイアウト（全幅共通）
- [ ] システムは、本文の幅を最大 720px で表示する
- [ ] システムは、パンくず（1024px 以上）または「テックブログ」への戻るリンク（1024px 未満）、タグ、タイトル、説明文、著者（画像・名前・役割）、公開日、読了時間を、アイキャッチより上に表示する
- [ ] システムは、タイトルをアイキャッチに重ねない
- [ ] システムは、アイキャッチを本文と同じ幅、16:9 で切り抜いて表示する
- [ ] システムは、本文の後に「タグとシェア」「書いた人（画像・名前・役割）」「前後の記事」をこの順で表示する
- [ ] システムは、前後の記事の左に1つ古い記事（前の記事）、右に1つ新しい記事（次の記事）を表示する
- [ ] もし前後どちらかの記事が無ければ、システムはその位置に「テックブログ一覧へ」のリンクを表示する
- [ ] システムは、関連記事を最大3件、本文より下の別の帯に表示する。768px 以上では3列、768px 未満では横スクロールで並べる
- [ ] システムは、記事ページの `<main>` を1つだけにする（`Layout.astro` の `<main>` の中に `<main>` を入れない）
- [ ] 幅 320px 以上のどの画面幅でも、システムは横スクロールを発生させない（関連記事の横スクロール枠とコードブロックの中は除く）

### 目次の内容
- [ ] システムは、本文の h2 と h3 から目次を作る。h3 はその前の h2 の下に字下げして表示する。h2 より前にある h3 は字下げしない
- [ ] システムは、テキストが空の見出し（`<h2><br></h2>` など）を目次に含めない
- [ ] もし見出しに `id` が無い、または他の要素の `id` と重複していれば、システムはページ内で重複しない `id` を付ける
- [ ] もし目次に入る見出しが2つ未満なら、システムは目次・目次バー・目次ボタンを表示しない
- [ ] 目次の項目が選ばれたとき、システムはその見出しへ移動し、見出しにフォーカスを移す。見出しはヘッダーにも目次バーにも隠れない
- [ ] システムは、今読んでいる見出しを、右の列・目次バー・目次シートのすべての目次で示す。`aria-current="location"` を付け、太字と点で表す（色だけで区別しない）
- [ ] もし目次が画面に収まらない長さなら、システムは目次の中だけをスクロールできるようにする（右の列・目次バーの展開部分・シートのすべて）

### 1024px 以上
- [ ] システムは、目次を本文の右の列に表示する。右の列はアイキャッチの上端から始まる
- [ ] スクロールしている間、システムは右の列をヘッダーに重ならない位置で画面内に残す
- [ ] システムは、右の列の目次の下に、シェアボタン（X・Facebook・LinkedIn・リンクをコピー）と「ページの先頭へ」のリンクを表示する

### 768px 以上 1024px 未満
- [ ] システムは、ヘッダーの直下に目次バー（高さ 48px）を固定して表示する
- [ ] システムは、目次バーに今読んでいる見出しを1行で表示する。はみ出す分は省略記号にする
- [ ] 目次バーが押されたとき、システムは目次をバーの下に開く。バーには `aria-expanded` を付ける
- [ ] 項目が選ばれた・Escape が押された・バーと目次の外が押されたとき、システムは目次を閉じる。Escape で閉じたときは、フォーカスが目次の中にあればバーに戻す

### 768px 未満
- [ ] システムは、目次ボタン（直径 52px の円）を画面の左 16px・下 28px に表示する。入会申し込みの追従ボタン（右 16px・下 28px・高さ 52px）と左右対称になる
- [ ] 目次ボタンが押されたとき、システムは目次を画面の下からシートで開き、背景のスクロールを固定する
- [ ] 閉じるボタン・Escape・シートの外が押されたとき、システムはシートを閉じ、スクロールの固定を解除し、目次ボタンにフォーカスを戻す
- [ ] 項目が選ばれたとき、システムはシートを閉じ、スクロールの固定を解除してから、その見出しへ移動する

### 幅をまたいだとき
- [ ] もし目次バーの展開部分や目次シートを開いたまま画面幅が変わり、その目次が表示されない幅になったら、システムはそれを閉じる。このとき、非表示になったボタンへフォーカスを戻さない

### シェア
- [ ] システムは、リンクのコピーで記事の正規の URL（`https://tus-tnd.com/blog/<id>`）をコピーする。ページ内リンクの `#…` やプレビューのクエリは含めない
- [ ] リンクのコピーに成功したとき、システムはそのことを画面とスクリーンリーダーの両方に伝える

### 既存動作の維持
- [ ] 下書きプレビュー（`/blog/preview`）も、同じレイアウトで表示される
- [ ] `<head>` のメタ情報と構造化データ（`BlogPosting`）は変わらない
- [ ] ヘッダー・入会モーダル・メニューの見た目と動作は変わらない
- [ ] `Layout.astro` のラッパを変えたあとも、他のページ（トップ・about・ブログ一覧・FAQ・お問い合わせ・404）の見た目は変わらない
- [ ] `pnpm build`（`astro check` を含む）がエラー0で完了する

## Open questions
1. **読了バー（ヘッダー下の細い進捗線）を今回入れるか。** デザインにはあるが、目次の現在地の表示で、読んでいる位置はおおよそ分かる。記事側に `fixed` で置けばヘッダーには触れずに作れるが、ヘッダーの高さ（PC は 80→64px に縮む）に合わせる処理が要る。推奨：今回は入れない（範囲を絞るため）
2. **1024px 未満で Facebook・LinkedIn のシェアを残すか。** デザインでは、本文の後のシェアは「ポスト」と「リンクをコピー」の2つだけ。1024px 以上は右の列に4つあるが、1024px 未満では Facebook・LinkedIn が無くなる。推奨：本文の後のシェアに Facebook・LinkedIn をアイコンだけで足し、どの幅でも4つ出す
3. **本文中の h1 の扱い。** 本文にタイトルと同じ文言の h1 を入れている記事がある（例：shignate-mufg）。ページに h1 が2つになる。推奨：目次には含めない。本文の修正は Non-goal なので、microCMS 側で書いた人に直してもらうよう別途伝える
