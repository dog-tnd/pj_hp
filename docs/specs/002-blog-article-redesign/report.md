## やったこと
- `src/utils/toc.ts`：本文の h2・h3 から目次を作る。`id` が無い・重複する見出しに `toc-N` を付け、`tabindex="-1"` を付ける
- `BlogArticleView.astro` を作り直した
  - タイトルを画像から外して上に置き、本文を 720px にし、アイキャッチを本文と同じ幅（16:9）にした
  - 本文の後に「タグとシェア → 書いた人 → 前後の記事」を置き、関連記事は別の帯にした
  - `<main>` の二重を解消した
- 目次を3つの幅で出し分けた
  - lg 以上：右の列で追従
  - md〜lg：ヘッダー直下の目次バー
  - md 未満：左下の目次ボタンと目次シート（`<dialog data-scroll-lock>`）
- `src/scripts/article-toc.ts`：今読んでいる見出しの判定、項目を選んだあとの移動・フォーカス・ハッシュの更新、バーとシートの開閉
- `ShareButtons.astro` / `copy-link.ts`
  - シェアボタン4つを共通化した。どの幅でも4つ出る
  - コピーするのは正規の URL。結果は `aria-live` で読み上げる
- `Layout.astro`：ラッパに `overflow-clip` を足し、sticky が効くようにした
- `[slug].astro`：前＝1つ古い記事、次＝1つ新しい記事に直した
- `src/dev-pages/blog-article.astro`：見出しのパターン別のサンプル（dev 限定）

## デザイン・spec から変えた点
| 箇所 | デザイン / spec | 実装 | 理由 |
|---|---|---|---|
| dev ページの描画 | spec に記載なし | `prerender = false`（リクエストごとに描画） | dev でも静的ページ扱いだとクエリ（`?case=`）が渡らないため。`/blog/preview` と同じ方法 |
| dev ページの「id の重複」サンプル | 段落と見出しで重複させる想定 | 見出しどうしで重複させた | 段落の `id` はサニタイズで消えるため、段落とは重複しようがない |
| 目次シートを閉じたときのスクロール固定の解除 | `close` イベントで `syncScrollLock()` | 自分で閉じるとき（閉じるボタン・背景・項目・幅の変化）は、`close()` の直後にも呼ぶ | `close` イベントが届くまでの間、固定が残ることがあったため（検証で発見） |
| スマホの本文の文字サイズ | キャンバスは 16px | 既存どおり `prose-lg`（18px） | 本文の装飾の変更は Non-goal |

## デザインに無く、判断で決めた点
| 箇所 | 決めた内容 | 根拠 |
|---|---|---|
| アイキャッチ・著者画像の `alt` | 空にした（以前はタイトル・著者名） | すぐ隣にタイトル・著者名が文字であり、読み上げが重複するため |
| タグ | `<ul aria-label="タグ">` の一覧にした（リンクにはしない） | タグページは Non-goal。並びとして伝えるため |
| 右の列の幅 | 280px | 本文 720px ＋ 間 80px ＋ 280px が 1120px に収まる |
| 右の列の目次の最大の高さ | 画面の高さ − 316px（シェアと先頭への分）で、中だけスクロール | 長い目次（12項目）でもシェアが画面から出ないため |
| 目次バーのボタンの名前 | 「目次：〈今の見出し〉」（「：」は読み上げ専用） | spec の ARIA の指定どおりに読ませるため |
| 項目を押したあとの判定の停止 | 最大1秒止め、`scrollend` が来たらすぐ再開 | なめらかな移動の途中で現在地がちらつくため。`scrollend` 非対応のブラウザでも1秒で戻る |

## 未確認・注意点
- **実機（iOS Safari / Android Chrome）は未確認。** 特に、ボトムシートの `dvh`、`overflow: clip`（Safari 16 以上）、`scrollend`（非対応なら1秒の待ちで代替）
- **実際のクリップボードへの書き込みは未確認。** 検証では `navigator.clipboard.writeText` を差し替えて、渡す文字列を確かめた
- PC でページの先頭から目次で移動したとき、ヘッダーが 80px から 64px に縮む途中のため、着地が少し上にずれる可能性がある（spec に記載済み）。今回はスクロール後の状態でしか測っていない
- メニューや入会モーダルが開いている間に目次バーの Escape が反応しないことは、コードでは対応したが動作は未確認
- 既存の `TwoLine`（右上の十字線）が、記事ヘッダーの右上に重なって見える。develop でも同じ位置に出ており、今回は Non-goal として触っていない
- 既存の `.prose` 向けの独自スタイル（`BlogArticleView.astro` の `<style>`）は、スコープ付きのため本文に当たっていない（spec に記載済み）。消すか効かせるかは別の作業で判断してほしい
- 既存の入会ボタン（白文字に `#F5BF48`）は、文字のコントラストが 4.5:1 に届かない（今回の変更とは無関係）
