# よくある質問ページの刷新 requirements

## 目的
よくある質問ページ（`/faq`）を、上部固定ヘッダーと記事ページ（spec 002）の作りに合わせて作り替える。あわせて次の3つを行う。

- 質問と回答を microCMS で管理し、文言の変更をコードの変更なしにできるようにする
- 表示と同じデータから `FAQPage` の構造化データを出力する（spec 003 の D4、#74 の「FAQ のデータ化と FAQPage」）
- 全ページ共通の背景（右上のぼかし1個）を、大きなぼかしを左右交互に複数置く形に変える

## Non-goals
- 質問・回答の文言の見直し（microCMS への移行時は今の文言をそのまま入れる）
- FAQ の検索機能
- ヘッダー（`HeaderDesktop` / `HeaderMobile`）と入会モーダルの変更
- `/faq` 以外のページの h1 の付け直しやトップの事実ブロック（#74 の他の項目）。`/faq` の h1（「よくある質問」を1つ）は対象に含める
- お問い合わせページ・記事ページ・about の作りの変更（背景の変更で見え方が変わる分を除く）
- マシュマロのロゴ・キャラクターの使用（利用条件が確認できないため使わない）

## ユーザーストーリー
- 入会を考えている新入生として、知りたい質問をすぐ見つけたい。なぜなら、入会前の不安（初心者でも大丈夫か、いつ入れるか）を早く解消したいから。
- 新入生として、ページ内検索で質問を探したい。なぜなら、カテゴリを選ばなくても目的の質問にたどり着きたいから。
- ここに無い質問がある新入生として、名前を出さずに気軽に質問したい。なぜなら、問い合わせフォームは敷居が高いから。
- サークルの運営メンバーとして、質問と回答を管理画面から更新したい。なぜなら、文言は今後変わる見込みで、そのたびにコードを直したくないから。

## 受け入れ条件

### データ（microCMS）
- [ ] システムは、質問と回答を microCMS の `faq` API から、カテゴリを `faq-categories` API から、ビルド時に取得する。下書きは含めない
- [ ] システムは、カテゴリを `sortOrder` の昇順、各カテゴリ内の質問を `sortOrder` の昇順で表示する。`sortOrder` が同じときは作成日時の古い順にする
- [ ] システムは、質問が1つも無いカテゴリを表示しない
- [ ] もし公開中の質問が0件、質問のカテゴリが取得できない（参照切れ）、またはカテゴリの `slug` が重複・不正なら、システムはビルドを失敗させ、理由をログに出す（直前のデプロイが残る）
- [ ] システムは、回答の改行コードを `\n` にそろえ、空行（空白だけの行を含む）で段落を分ける。段落内の改行は改行として表示する

### レイアウト
- [ ] システムは、見出し（飾りの「FAQ」・h1「よくある質問」・説明文）、質問の一覧、「ここにない質問は」、フッターをこの順に表示する。h1 はページに1つ
- [ ] システムは、質問をカテゴリごとの見出し（h2）の下にまとめ、全カテゴリを1ページに並べる（カテゴリで絞り込まない）
- [ ] システムは、カテゴリの見出しに名前と質問の数を表示する。数は「3件」のように読み上げられる
- [ ] システムは、各カテゴリの質問を白い面（枠線つき）にまとめて表示する
- [ ] 1024px 以上では、システムは質問の一覧を最大 720px、カテゴリの一覧を右の列（280px）に表示する。右の列はスクロールしても、ヘッダーに重ならない位置で画面内に残る
- [ ] 1024px 未満では、システムはカテゴリの一覧をヘッダーの直下に固定し、横スクロールで並べる
- [ ] 幅 320px 以上のどの画面幅でも、システムは横スクロールを発生させない（カテゴリの横スクロール枠の中は除く）

### カテゴリの一覧
- [ ] システムは、各カテゴリの名前と質問の数を表示する
- [ ] カテゴリが選ばれたとき、システムはそのカテゴリの見出しへ移動し、見出しにフォーカスを移す。見出しはヘッダーにもカテゴリの行にも隠れない
- [ ] システムは、今見ているカテゴリを `aria-current="location"` と、太字・点（1024px 以上）または反転（1024px 未満）で示す（色だけで区別しない）
- [ ] 1024px 未満で今見ているカテゴリが変わったとき、システムはカテゴリの行を横にスクロールして、そのカテゴリを見える位置に出す（ページは縦に動かさない）

### 質問の開閉（アコーディオン）
- [ ] JavaScript が動く環境で初めてページを開いたとき、システムはすべての回答を閉じて表示する
- [ ] 質問が押されたとき、システムはその回答を開閉する。質問のボタンには `aria-expanded` と `aria-controls` を付ける
- [ ] システムは、閉じている回答もページ内検索で見つかるようにする。検索で見つかった回答は開く（対応しているブラウザのみ）
- [ ] ページを開いたとき、または URL のハッシュが変わったときに、ハッシュが質問を指していれば（`/faq#q-…`）、システムはその回答を開き、その質問へ移動してフォーカスを移す
- [ ] 「すべて開く」が押されたとき、システムはすべての回答を開き、ボタンの文言を「すべて閉じる」に変える。「すべて閉じる」はその逆
- [ ] 1つでも閉じている回答があるとき、システムはボタンの文言を「すべて開く」にする。個別の開閉・ページ内検索・ハッシュで開いたときも文言を更新する

### ここにない質問は
- [ ] システムは、マシュマロとお問い合わせフォームの2つの入口を表示する。768px 未満ではマシュマロを先に表示する
- [ ] システムは、マシュマロの入口に、マシュマロのロゴではなく自前のアイコン（吹き出し＋？）を表示する
- [ ] 「マシュマロで質問する」が押されたとき、システムは TND のマシュマロのページを新しいタブで開く。新しいタブで開くことを読み上げでも伝える
- [ ] 「お問い合わせ」が押されたとき、システムは `/contact` を開く

### 構造化データ・メタ
- [ ] システムは、表示しているのと同じ質問・回答から `FAQPage` の構造化データ（JSON-LD）を出力する
- [ ] システムは、`/faq` に spec 003 と同じ `description` を出力する（main と同じ文言）

### 背景（全ページ）
- [ ] システムは、全ページの背景に、大きなぼかしを左右交互に複数置く。ぼかしは本文の後ろに表示し、クリックや選択を妨げない
- [ ] システムは、ぼかしで横スクロールを発生させない
- [ ] 背景を変える前後で、全ページのぼかし以外の要素（位置・大きさ・文字）は変わらない。ぼかしは、背景が透明な部分（地色・半透明のヘッダー）を通して見える。記事ページのように本文の背景が全幅を覆うページでは、見えなくてよい

### 既存動作の維持
- [ ] ヘッダー・入会モーダル・メニューの動作は変わらない
- [ ] `pnpm build`（`astro check` を含む）がエラー0で完了する

## 決定事項（2026-10-17、人間）
- D1：カテゴリでの絞り込みをやめ、全カテゴリを見出し付きで並べる。カテゴリはその場所へ移動するリンクにする（デザインで合意）
- D2：背景のぼかしは `Layout.astro` で全ページに入れる
- D3：質問と回答は microCMS で管理する
- D4：`FAQPage` の構造化データを今回に含める（#74 の「FAQ のデータ化と FAQPage」はこの PR で済ませる）
- D5：「マシュマロで質問する」ボタンは、マシュマロの色（通常 `#E69A9C`・ホバー `#EDBEC0`）に白文字とする。白文字のコントラスト比は約2.2:1（ホバー時 約1.6:1）で、WCAG の基準（4.5:1）を満たさないことを承知のうえで採用する
- D6：マシュマロのロゴ・キャラクターは使わない。利用規約上、知的財産権は運営に帰属し、外部での利用条件が示されていないため
- D7：背景の色は、サイト共通の gray-50 の地色に、メインビジュアル（`mainCharm.svg`）の青・青紫・水色のぼかしを重ねる
