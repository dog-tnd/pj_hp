# 「プログラミングサークル」検索での AI による概要対策 requirements

## 目的
Google で「プログラミングサークル」と検索したときの「AI による概要」に、TND（tus-tnd.com）が引用されるようにする。
AI による概要は通常の検索と同じ評価（クロールできる本文・構造化データ・被リンク）で引用元を選ぶ。専用の設定は無いため、次の3つで対策する。
1. ページの主題と事実を、機械が読める形（meta・構造化データ）で正確に渡す
2. 引用されやすい「短い事実の文」を本文に置く
3. 外部から tus-tnd.com へのリンクを増やす（コード外。人間が行う）

## フェーズ
develop は main より 34 コミット先行しており、全ページが改修済み。衝突を避けるため2段階に分ける（決定事項 D1）。

| フェーズ | ブランチ | 範囲 |
|---|---|---|
| 1（本 spec の実装対象） | main から切った `feature/seo-ai-overview` | `<head>` の中だけ。画面の見た目は変えない |
| 2（別 PR） | develop | 見出し（h1）・本文の追加、FAQ のデータ化と `FAQPage`、OG 画像。本 spec の「フェーズ2」節に方針だけ記す |

## Non-goals（フェーズ1）
- 画面に表示される要素（見出し・本文・レイアウト・スタイル）の変更
- ブログ記事ページ（`/blog/[slug]`）の構造化データ。PR #73 と衝突するため
- about ページの本文。PR #69（develop 向け）で刷新中のため。`<Layout>` の `description` 追加だけ行う
- OG 画像の差し替え（SVG→PNG）。新しい画像素材が要るためフェーズ2
- `/faq` の `FAQPage` の構造化データ。FAQ の改修で文言が大きく変わる可能性があり、表示とずれるため（D4）。`<Layout>` の `description` 追加だけ行う
- `llms.txt`。Google は llms.txt を使わない方針を示しているため作らない
- `meta keywords` の削除・整理（Google は無視するが害も無い）
- 被リンク獲得などコード外の施策

## ユーザーストーリー
- 大学のプログラミングサークルを探している高校生・大学生として、AI による概要に具体的なサークル名と特徴（規模・初心者比率・活動内容）が出てほしい。なぜなら、一般論より実例のほうが選ぶ参考になるから。
- TND の広報担当として、検索結果や AI による概要で TND が正しい事実（非公認・野田キャンパス・約40名）で紹介されてほしい。なぜなら、誤った紹介は新歓に悪影響だから。

## 受け入れ条件（フェーズ1）

### サイト全体（`Layout.astro`）
- [ ] システムは、全ページの構造化データ（JSON-LD）を `@graph` で出力し、`Organization` と `WebSite` を含める
- [ ] システムは、`Organization` に名前・別名（「東京理科大学プログラミングサークルTND」など）・説明・URL・ロゴ・設立年・活動場所（東京理科大学 野田キャンパス、千葉県野田市）・扱う分野（`knowsAbout`）・SNS（X・GitHub）を含める
- [ ] システムは、`Organization` に `memberOf` / `parentOrganization` を含めない（D3）
- [ ] システムは、構造化データの説明文に、サイト内のどこかに表示されている事実だけを書く
- [ ] システムは、`WebSite` にサイト名「TND」と別名を含め、発行者として `Organization` を `@id` で参照する
- [ ] システムは、`og:locale` に `ja_JP` を出力する
- [ ] システムは、Twitter カードのメタタグを `name` 属性で出力する
- [ ] システムは、JSON-LD の文字列中の `<` を `\u003c` にエスケープする
- [ ] システムは、`description` を渡さないページに、事実（設立年・人数・活動分野）を含む既定の説明文を出力する

### ページごとの meta
- [ ] システムは、トップ・私たちについて・よくある質問・お問い合わせ・ブログ一覧に、それぞれ固有の `description` を出力する
- [ ] システムは、トップの `<title>` を「プログラミングサークル」が前半に来る形にする
- [ ] システムは、各 `description` を 70〜120 字に収める

### 品質
- [ ] `pnpm build` が成功する
- [ ] 出力した JSON-LD がすべて `JSON.parse` できる
- [ ] 画面の見た目が変わらない（変更前後のビルド結果で、全ページの `<body>` が一致する）

## フェーズ2（develop・別 PR）の方針
実装は本 spec の範囲外。issue #74 で管理する。develop で着手するときに、この節を元に別 spec を作る。

1. **h1**：ヘッダーのロゴ「TND」を h1 から外し、各ページの主見出しを h1 にする。トップの h1 は「東京理科大学のプログラミングサークル TND」とする（D2）
2. **トップの事実ブロック**：設立年・人数・初心者比率（9割）・チーム・活動頻度・会費・募集時期を、短い文または定義リストで並べる。AI による概要がそのまま引用できる形にする
3. **FAQ のデータ化と `FAQPage`**：FAQ の改修に合わせて質問・回答を配列にまとめ、表示と `FAQPage` の構造化データを同じデータから生成する（D4）
4. **OG 画像**：1200×630 の PNG を作る。X・Facebook は SVG をプレビューに使えないため
5. **ブログ記事の `publisher`**：`Organization` の `@id` を参照する（#73 のマージ後）
6. **`/blog/` がインデックスされない原因の調査**：記事への内部リンクの起点なので、本文の量・内部リンク・クロールの状況を調べる
