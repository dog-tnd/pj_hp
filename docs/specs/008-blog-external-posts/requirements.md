# 外部サイトの記事の混在 requirements

## 目的
メンバーが Zenn・Qiita などの外部サイトに書いた記事を、`/blog` の一覧とトップの「新着記事」に、自サイトの記事と同じ並びで表示する（Issue #70。#71 のドラフトを引き継ぐ）。

- 技術記事は外部サイトで多くの人に読んでもらいつつ、TND の活動としては1か所で見られるようにする
- 外部サイトの記事は、押すと新しいタブでそのサイトが開くことが、見て分かるようにする
- このブランチで作るのは、外部サイトの記事の仕組みと、外部サイトの記事に付けるバッジだけ（D4）

## Non-goals
- 既存のデザインの変更（D4）。ブログ一覧のカード（`NewsCard`）・タグの絞り込み・並べ方・トップの新着記事の形は develop のまま
- 外部サイトから記事の情報を自動で取得すること（Zenn・Qiita の API・RSS・OGP は使わない。#70 の決定）
- 外部サイトの記事のページを自サイトに作ること（`/blog/{id}` は自サイトの記事だけ）
- 記事ページ（`/blog/[slug]`）の「関連記事」「前後の記事」に外部サイトの記事を入れること
- microCMS の `blog` API の変更
- ヘッダー・フッター・入会モーダル・背景のぼかしの変更

## ユーザーストーリー
- 新入生として、TND のメンバーがどんな技術記事を書いているかを一覧でまとめて見たい。なぜなら、サークルで何ができるようになるかを知りたいから。
- メンバーとして、Zenn・Qiita に書いた記事を TND のサイトにも載せたい。なぜなら、記事は読まれやすい場所に書きつつ、サークルの活動としても見せたいから。
- 管理者として、外部サイトの記事を microCMS に URL などを入れるだけで載せたい。なぜなら、コードを変えずに更新したいから。

## 受け入れ条件

### 外部サイトの記事の登録（microCMS）
- [ ] 管理者は、microCMS の外部サイトの API（D7）に、URL・サイトの種類（Zenn／Qiita／その他）・タイトル・説明文・著者名・著者アイコン（任意）・役割（任意）・サムネイル（任意）・タグ（任意）を入れて公開できる
- [ ] システムは、外部サイトの記事を、microCMS で公開したものだけ表示する。下書きは表示しない
- [ ] URL が `https:` でないとき、またはサイトの種類が Zenn なのに `zenn.dev`、Qiita なのに `qiita.com` の URL でないとき、システムはその記事を表示せず、ビルドのログに理由を出す。ほかの記事の表示とビルドは止めない
- [ ] サムネイル・著者アイコンが空のとき、システムは自サイトの記事と同じサンプル画像を出す

### 並び順
- [ ] システムは、自サイトの記事と外部サイトの記事を、microCMS の公開日時（`publishedAt`）の新しい順に1つの並びにする（D1）
- [ ] システムは、カードの日付に microCMS の公開日時を `YYYY.MM.DD`（日本時間）で表示する

### ブログ一覧（`/blog`）
- [ ] システムは、外部サイトの記事を、自サイトの記事と同じ `NewsCard` で並べる。カードの見た目・列数・タグの絞り込みは develop のまま（D4）
- [ ] 自サイトの記事のカードが押されたとき、システムは同じタブで `/blog/{id}` を開く
- [ ] 外部サイトの記事のカードが押されたとき、システムは新しいタブで外部サイトの記事を開く
- [ ] システムは、外部サイトの記事のカードの画像に、サイトの名前（Zenn／Qiita／外部サイト）のバッジと外部リンクのアイコンを重ねる（D5）。カードの大きさは変えない
- [ ] システムは、外部サイトの記事のタグも、タグの絞り込みの対象と件数に入れる

### トップの「新着記事」（`/`）
- [ ] システムは、自サイトの記事と外部サイトの記事を合わせた並びの先頭4件を表示する（D3）。大きい1件と一覧3件の形は今のまま
- [ ] システムは、外部サイトの記事に、ブログ一覧と同じサイトの名前と外部リンクのアイコンを表示し、新しいタブで開く

### 下書きプレビュー（`/blog/preview`）
- [ ] 「一覧カードの見え方」は develop のまま（自サイトの記事の `NewsCard`）

### アクセシビリティ
- [ ] システムは、外部サイトの記事のリンクを「<タイトル>（Zenn の記事・新しいタブで開きます）」のように読み上げる。サイトの名前とアイコンは二重に読ませない

### 画面幅
- [ ] 幅 320px 以上のどの画面幅でも、システムは横スクロールを発生させない

### 既存動作の維持
- [ ] 外部サイトの記事が無いとき、`/blog`・`/`・`/blog/preview` の見た目と動きは develop と同じ
- [ ] 記事ページ（`/blog/[slug]`）の関連記事・前後の記事は、自サイトの記事だけで今と同じに動く
- [ ] `pnpm build`（`astro check` を含む）がエラー0で完了する

## 決定事項
- D1（2026-10-26、人間）：並び順と表示する日付は、外部サイトの記事も microCMS の公開日時（`publishedAt`）にする。#70 の「Zenn の公開日を手で入れる欄」は作らない。昔の記事を後から登録するときは、microCMS で公開日時を外部サイトの公開日に変える（README に書く）
- D2（2026-10-26、人間）：microCMS に外部サイトの記事用の API を新しく作る。サイトの種類は Zenn・Qiita・その他の3つ。`blog` API とは統合しない（#70 の決定を引き継ぐ）
- D3（2026-10-26、人間）：トップの「新着記事」にも外部サイトの記事を混ぜる
- D4（2026-10-26、人間）：スコープは、外部サイトの記事の仕組みと外部サイトのバッジの追加だけ。既存のデザイン（ブログ一覧のカード・タグの絞り込み・トップの新着記事の形）は変えない
- D5（判断）：サイトの名前は、Zenn は「Zenn」、Qiita は「Qiita」、その他は「外部サイト」と出す。#70 の「Zenn」バッジの見た目を3種類に広げる
- D6（判断）：#71 のブランチ（`develop-before-designupdate` が土台）は使わず、develop から新しいブランチで作り直す。#71 の `blog-cards.ts` の考え方（共通の形にそろえて日付順に並べる）は引き継ぐ。マージのときは @zawaumi さんを `Co-authored-by` に入れる
- D7（2026-10-26、人間）：microCMS の API は「外部サイト」（エンドポイント `external-posts`）を使う。欄の ID は design の表どおり
